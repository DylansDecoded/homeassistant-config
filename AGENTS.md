# AGENTS.md

This file provides guidance to Codex (Codex.ai/code) when working with code in this repository.

## Overview

Home Assistant configuration for a residential smart home (Robson Manor). HA runs in Docker (`docker-compose.yaml`) using the official image pinned to a specific version. All configuration lives under `config/`.

## Running / Reloading

```bash
# Start Home Assistant
docker compose up -d

# Stop
docker compose down

# View logs
docker compose logs -f homeassistant

# Restart to pick up configuration changes
docker compose restart homeassistant
```

HA validates configuration on startup. Many changes (automations, scripts, groups, input_booleans) can be reloaded via the HA UI (Developer Tools → YAML → Reload) without a full restart.

External access: `https://hass.robsonhome.cloud` via Traefik reverse proxy. Internal: `http://hass.internal`.

## Configuration Architecture

`config/configuration.yaml` is the root config. It uses two inclusion patterns:

- **Single-file includes** (`!include`): `scripts.yaml`, `scenes.yaml`, `sensors.yaml`, `binary_sensors.yaml`, and `homekit.yaml`
- **Directory merge includes** (`!include_dir_merge_list` / `!include_dir_merge_named`): `automations/` and `groups/`

Automations use the directory-based approach. New hand-written automations go in their own file under `config/automations/`.

### Where things live

| Domain | Location |
|--------|----------|
| Automations (UI-managed) | `config/automations/automations.yaml` |
| Automations (hand-written) | `config/automations/*.yaml` (other files) |
| Scripts | `config/scripts.yaml` |
| Scenes | `config/scenes.yaml` |
| Groups | `config/groups/*.yaml` |
| HomeKit bridge config | `config/homekit.yaml` |
| Binary sensors | `config/binary_sensors.yaml` |

### Custom components (via HACS, gitignored)

- `teamtracker` — sports score sensors (used for Bengals touchdown automation)
- `localtuya` — local Tuya device control
- `pirateweather` — weather integration

## Key Conventions

- Secrets go in `config/secrets.yaml` (gitignored). Reference with `!secret key_name`.
- Entity IDs follow `domain.descriptive_name` (e.g. `switch.front_porch_switch`, `climate.upstairs_thermostat`).
- Automations generated by the HA UI editor are written to `config/automations/automations.yaml` and include numeric `id` fields. Hand-written automations use descriptive string IDs.
- HomeKit filter in `homekit.yaml` controls what's exposed to Apple Home — update it when adding new entities that should appear in the Apple Home app.
- The `groups/interior_lighting` and `groups/exterior_lighting` groups are used by automations (e.g. alarm triggers all interior lights).
